# stdx bit_set.Scratch versus z53's local ScratchSet

Environment: aarch64-linux, Neoverse-V3, Zig 0.16.0, ReleaseSafe, native CPU,
stdx `4e82330`. The local implementation is the one z53 carried before the stdx
update; the two share the same dirty-word logic.

Method: alternating binaries, five runs per mode, three 100 ms trials per case,
compared with `benchstat` from goperf. All other code was identical.

## Inline patch

Changing only `fn wordIsSet` to `inline fn wordIsSet` in the stdx source
recovered the difference:

## Reading

The `Scratch` methods instantiate in the consumer, but the private `wordIsSet`
helper does not inline across the module boundary. z53 adopts `Scratch` and
accepts the regression until baskingspot/stdx#16 fixes that.
